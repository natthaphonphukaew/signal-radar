# Signal Radar

**An AI-enabled dashboard that surfaces strategic signals across Thailand's economic, business, industry, consumer and social trends — collected, analysed and published automatically.**

## The problem

Strategy and product teams need to know what is shifting in the market, but scanning dozens of news sources by hand is slow, repetitive and easy to drop when things get busy. It is exactly the kind of recurring manual workflow that should be automated.

## What this does

Every 6 hours, without anyone touching it:

1. **Collects** articles from 10 public RSS feeds (Google News queries + Thai tech/business publishers).
2. **Normalises** them — strips HTML, removes duplicates, balances sources so one outlet cannot dominate.
3. **Analyses** the batch with an LLM (Gemini), clustering related articles into distinct *signals*.
4. **Validates** the output, then **publishes** it as a static JSON file the dashboard reads.

Each signal carries a **"So what?"** — one sentence on the business implication — which is the part a strategy team actually needs.

## Architecture

```
GitHub Actions (cron: every 6h)
   │
   ├── 1. collect.mjs   → fetch + parse RSS            (no API key)
   ├── 2. normalise     → strip HTML, dedupe, cap N
   ├── 3. analyze.mjs   → Gemini, JSON schema mode     (key from GitHub Secrets)
   ├── 4. validate      → drop unsupported signals
   └── 5. write         → public/data/signals.json
              │
              └── commit → Vercel auto-redeploy → dashboard serves fresh data
```

**The browser only ever reads a static JSON file.** No backend, no server cost, and the API key never leaves CI.

### Design decisions worth calling out

| Decision | Why |
|---|---|
| LLM runs in CI, not in the browser | A static site cannot hold a secret. Running the model in GitHub Actions keeps the key safe and the hosting free. |
| Model returns **article IDs**, never URLs | The model physically cannot invent a source. IDs are resolved back to real articles after the call; unknown IDs are dropped. |
| Structured output (`responseSchema`) | Guarantees parseable JSON instead of scraping prose with regex. |
| One batched LLM call per run | Keeps the whole thing inside the Gemini free tier. |
| Fail closed | If any step fails, the run exits non-zero and **leaves the previous `signals.json` untouched** — the dashboard never shows a broken state. |
| Feedback stored per viewer | 👍/👎 re-ranks signals and is kept in `localStorage`, so the feedback loop works with no backend. |

## Dashboard features

- **Stat tiles** — signals surfaced, dominant category, average impact, sources scanned
- **Charts** — category and impact distribution (hand-rolled inline SVG, no chart library)
- **Filtering** — by category, time horizon, minimum impact, and full-text search
- **Signal cards** — impact meter, confidence, time horizon, "So what?", and expandable real sources
- **Relevance feedback** — 👍/👎 re-ranks the list and persists locally
- **Light / dark themes**, fully responsive

## Running it locally

```bash
npm install
npm run dev          # dashboard on http://localhost:5174 (uses bundled sample data)
```

To generate real signals you need a free Gemini key from [Google AI Studio](https://aistudio.google.com/apikey):

```bash
cp .env.example .env         # add your GEMINI_API_KEY
npm run collect              # step 1 only — check the feeds work
npm run pipeline             # full run → writes public/data/signals.json
```

> If the free-tier model id changes, override it with `GEMINI_MODEL` rather than editing code.

### Automating it

1. Push to GitHub.
2. Add repo secret **`GEMINI_API_KEY`** (Settings → Secrets and variables → Actions).
3. The workflow in `.github/workflows/collect.yml` runs every 6 hours, and can be triggered manually with **Run workflow**.
4. Connect the repo to Vercel — each committed data refresh redeploys automatically.

## Project structure

```
pipeline/
  feeds.js         # RSS sources and run limits
  collect.mjs      # fetch, parse, normalise, dedupe
  analyze.mjs      # Gemini call + validation (the anti-hallucination logic)
  run.mjs          # orchestrator; fails closed
  make-sample.mjs  # dev utility that builds the bundled sample data
src/
  lib/signals.js   # loading, ranking, formatting
  hooks/           # theme + feedback persistence
  components/      # StatTiles, Charts, FilterBar, SignalCard
public/data/
  signals.json     # generated by the pipeline
  sample.json      # committed fallback (real sources, placeholder analysis)
```

---

## Notes and limitations

- Sample data ships with **real articles** from a live collector run, but its analysis text is hand-written placeholder — the banner in the UI says so. Real runs replace it with model output.
- Signals are only as good as the feeds; RSS gives headline and blurb, not full article text.
- Confidence is the model's own estimate, not a statistical measure.
